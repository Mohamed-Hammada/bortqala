# Production execution / تنفيذ الإنتاج

**EN:** A planned production order may inspect the current BOM for pre-start readiness. Starting the order freezes one tenant-scoped requirement row per component before any stock issue. Every active-order readiness check, completion-cost calculation, and cancellation reversal reads the frozen requirement set and never the mutable BOM. Completion totals the persisted valuation evidence of the production issue movements. Cancelling an in-progress order restores the exact issued quantity at the weighted unit cost derived from those persisted issue-cost rows; it never reprices the reversal from the latest inventory cost. Missing or incomplete issue valuation evidence fails closed with `MFG_ISSUE_VALUATION_EVIDENCE_REQUIRED`. Snapshot uniqueness and the order version protect retries from duplicate requirements and state transitions.

**قاعدة عكس التكلفة:** عند إلغاء أمر إنتاج قيد التنفيذ، تعيد الخدمة الكمية المصروفة نفسها بالتكلفة المرجحة المستخرجة من سجلات تكلفة الصرف المحفوظة، ولا تستخدم أحدث تكلفة مخزون. إذا كانت أدلة التقييم مفقودة أو غير مكتملة تفشل العملية بالرمز `MFG_ISSUE_VALUATION_EVIDENCE_REQUIRED`.

**BOM applicability and identity:** Order creation and start both require an active BOM whose effective-date window contains the production start date. Starting freezes the exact revision label (for example `v1.10-beta`) in every component snapshot; revision labels are never converted to lossy integers.

**AR:** يمكن لأمر الإنتاج المخطط استخدام قائمة المواد الحالية لفحص الجاهزية قبل البدء. عند البدء تحفظ الخدمة متطلباً ثابتاً ومعزولاً للمستأجر لكل مكوّن قبل أي صرف مخزني. بعد ذلك تعتمد الجاهزية وتكلفة الإكمال وعكس الإلغاء على المتطلبات المجمدة فقط ولا تقرأ قائمة المواد القابلة للتعديل. تجمع تكلفة الإكمال أدلة تقييم حركات صرف الإنتاج المحفوظة، وتحمي فريدة اللقطة وإصدار أمر الإنتاج من تكرار المتطلبات وانتقالات الحالة.

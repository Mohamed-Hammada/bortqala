# Workforce — Contractor Daily-Wage Module (عمال المقاولين اليوميون)

**EN:** Complete contractor-workforce lifecycle (Sessions 3+; roadmap item 27 attribution V322–V323): labor requests → contractor supplies worker batch → worker assignment → manual attendance (no fingerprint) → attendance lock → 15-day settlement periods → advances & deduction adjustments → settlement review/approval → finance journal posting + partner ledger → supplier invoice link → payment/disbursal. Worker categories mirror HR categories; project attribution syncs costs to the projects cost ledger.

**AR:** دورة حياة كاملة لعمال المقاولين اليوميين: طلبات العمالة ← توريد دفعة عمال من المقاول ← الإسناد ← حضور يدوي دون بصمة ← إقفال الحضور ← فترات تسوية نصف شهرية ← السلف والخصومات ← مراجعة التسوية واعتمادها ← ترحيل القيود ودليل الحسابات ← ربط فاتورة المورد ← الصرف. فئات العمال توازي فئات الموظفين، وتُحمَّل التكاليف على المشاريع تلقائياً.

- Key files: `domain/WorkforceAdvanceInstallment.java`, `application/WorkforceAdvanceService.calculateEmployeePayrollDeduction(...)` (consumed by PayrollService), settlement line/adjustment aggregates (V104–V105 schema).
- Deduction policy (WP-07, V350): `WorkforceAdvanceService.resolveDeductionPolicy(employeeId, categoryId, date)` resolves EMPLOYEE → EMPLOYEE_CATEGORY → GLOBAL → defaults (AUTO + MONTHLY) from the versioned `workforce_advance_policies` store (V58; synonyms `AUTO_IN_PAYROLL`→`AUTO`, `MANUAL_BUTTON`→`MANUAL` canonicalized at persistence). MANUAL resolution gates payroll auto-collection (`isManualDeductionPolicy`; zero advance with an `ADVANCE_DEDUCTION` skip-evidence explanation row) and enables the idempotent manual endpoint `POST /api/v1/workforce/advances/apply-deduction?periodId=YYYY/M` (ledger-notes replay detection, overdue installments capped by remaining balance). Policy CRUD validation: `ADVANCE_POLICY_INVALID`, overlapping open versions → `ADVANCE_POLICY_EXISTS`. Read resolver: `GET /api/v1/workforce/advances/resolved-policy`.
- Idempotency: settlement posting uses `operationId`; reversals reverse advance settlements symmetrically.
- Frontend: `fe/src/app/features/workforce` (pages/ui/data-access/models) incl. `ContractorSettlementDetailModalComponent`; settings business tab hosts the advances-policy card, employees page carries the gated apply-deduction action.
- Gap tracked: client-side revenue billing for manpower-supply companies = WP-17 (implementation guide).

**AR — سياسة خصم السلف (WP-07، V350):** يُحدِّد `resolveDeductionPolicy` السياسة الفعالة بترتيب الموظف ← فئة الموظف ← عام ← الافتراضي (تلقائي + شهري) من مخزن سياسات السلف المُصدَّر. عندما تكون السياسة «يدوي» لا يخصم كشف الرواتب أي سلف تلقائياً (مع صف إثبات تخطٍّ من نوع ADVANCE_DEDUCTION)، ويصبح التحصيل عبر نقطة النهاية اليدوية `POST /api/v1/workforce/advances/apply-deduction?periodId=YYYY/M` القابلة لإعادة التنفيذ بأمان لكل (موظف، فترة). التحقق من الحفظ: `ADVANCE_POLICY_INVALID` ورفض الإصدارات المفتوحة المتداخلة بـ `ADVANCE_POLICY_EXISTS`. واجهة الإعدادات تعرض بطاقة السياسات، وصفحة الموظفين تحمل زر «تطبيق الخصم» الذي يظهر فقط عند فعالية سياسة يدوية.
